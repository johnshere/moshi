## 1 背景与目标

三件事驱动本轮开发：

1. **插件运行日志需要保留**：`moshi` 插件已能通过 Magpie 网关注入（identity/session 已修好），但排查"注入了什么、为什么没注入"必须看注入台账。它与 `query_log`（检索正式日志）职责不同——trace 回答"插件在宿主里跑了没有、注入多少、失败在哪"，query_log 回答"检索为什么给这几条"。两者即使字段重叠也同时保留。
2. **query_log 膨胀**：钩子每次召回写一行、每行约 4.4KB（`query_text`/`fused_json` 是大头），3 天达 17.9MB。需要保留时长开关（默认 3 天，可改，0=永久）与一键清除。
3. **接入点会变多**：现在有 Magpie 网关插件与 MCP 两个接入适配器，后续还会有 Claude Code / DSH 直连、其它宿主插件。日志与界面不能写死"只有 Magpie"。

目标：

- 一级菜单新增 **「接入」（Access）**：下面是 **日志** 与 **接入点** 两页；原「设置 → Hook 接入」页迁入。
- 日志页三段：右上角**只读状态 + 跳转设置**、中部**按接入点实时总览**、底部**可搜索的瀑布流日志列表**。
- 设置页是**唯一写入口**：查询日志保留时长与清空、插件运行日志档位/上限/保留与清空，全在设置页；日志页只展示与跳转。
- query_log 增加接入点维度列，MCP 调用也进同一条日志流。
- Trace 功能改名 `hook_plugin_trace`，默认关闭；正式发版**整块摘除**。

## 3 概念与口径

### 3.1 接入层

接入层 = 所有把外部请求引到 core 的**入口适配器**。当前四个：

| 接入点 | 协议 | 能力（现状） | 身份来源 | 预算 |
| --- | --- | --- | --- | --- |
| Magpie 网关插件 `moshi` | gateway hook（`moshi-hook/1`） | recall、signal | 宿主 ctx（session/cwd），缺失时用会话开头指纹 | ≤800ms/次 |
| MCP 服务 `moshi` | MCP tools | `memory_query` / `memory_annotate` / `memory_feedback` / `memory_correct` | MCP 客户端会话；无 cwd 时 global | 无钩子预算 |
| CLI | 命令 | 全部（导入/导出/评测/配置/维护） | 本机 | 无 |
| 界面 | HTTP API | 管理面（查询/审核/配置/图谱/日志） | 本机 token | 无 |

MCP 是 core 能力的**子集适配器**，与钩子插件平级，不是独立体系。

### 3.2 接入点标识规约

- `caller_kind`：`gateway` | `mcp` | `cli` | `ui` | `eval` | `import`（后续 `agent`）。
- `caller_id`：`<kind>:<product>:<instance>`，例：`gateway:magpie:moshi`、`mcp:magpie:hub`、`cli:moshi`、`ui:moshi`；缺省 `unknown`。
- `plugin_id`：插件/适配器名（现在恒为 `moshi`），便于多插件共存。
- 规约写进详设，作为新增接入点的检查表。

### 3.3 设置 vs 日志页

- 设置页：唯一写入口。新增「设置 → 接入与日志」分组。
- 日志页：只读。右上角单行显示只读状态（如"查询日志 · 保留 3 天"、"插件日志 · 关闭"），点击跳 `settings#access-logs`。
- 破坏性操作（清空）只在设置页，二次确认 + audit。

### 3.4 Trace 定位

- 本质是**插件运行日志**（宿主内调用、注入字节、失败原因、回执号）。
- 默认 `off`；`summary` 只记结构化字段与哈希；`full` 才记正文且落盘前脱敏。
- 发版摘除：代码集中在 `src/core/hook/trace*.ts` + 一个配置节 + 一个路由 + 一个 CLI 子命令，删除即可。

## 4 阶段计划

### P1 配置改名（0.5 天）⏳

- 配置：删除 `debug:`，新增 `hook_plugin_trace:`（`level: off|summary|full`、`max_bytes`、`keep_days`；默认 off / 16MiB / 14 天）。
- 代码：`DebugSchema`→`HookPluginTraceSchema`、`cfg.debug`→`cfg.hook_plugin_trace`；`traceSink`/`trace.ts` 文案、CLI 标题统一"插件运行日志"。
- 文档：`config.example.yaml`、详设 §3.6、Hook 专题 §8.4。
- 验收：旧 `debug:` 配置会报错（strict）；新配置档位生效；`moshi hook trace` 文案更新；verify 绿。
- 说明：项目未发版，不做兼容。

### P2 query_log 数据面（0.5 天）⏳

- 迁移 `007_query_log_caller`：加列 `caller_id TEXT`、`caller_kind TEXT`、`plugin_id TEXT`、`corr_id TEXT`、`status TEXT`、`in_bytes INTEGER`、`out_bytes INTEGER`；索引 `(caller_id, ts)`、`(caller_kind, ts)`、`(corr_id)`。
- 写入：`searchWithPipeline` 调用方传入 caller；钩子把 `corr_id` 与插件名带进来；`memory_query` 走 `mcp:*`。
- 保留：`storage.query_log_keep_days`（默认 3，0=永久），daemon 启动 + 每日清理，分批删除。
- 验收：迁移后老行 caller 为 NULL 显示"未标注（历史）"；新行带 caller；清理后总量受控；真实库升级前备份。

### P3 日志 API（1 天）⏳

- `GET /api/logs?source=query|trace|all&caller=&kind=&status=&q=&cursor=&limit=20`
  统一事件形状：`{type, ts, caller_id, caller_kind, plugin_id, corr_id, status, in_bytes, out_bytes, latency_ms, preview}`；keyset 分页，两源各自游标合并。
- `GET /api/logs/summary?window=1h|24h|7d`：按接入点聚合（请求数、命中率、P95、降级分布、最近活动）+ 总量。
- 写接口归设置面：`PUT /api/config`（保留时长/档位）、`POST /api/maintenance/query-log/purge`、`POST /api/maintenance/trace/purge`。
- 验收：空库/有数据/两源混排分页不重不漏；搜索命中；summary 与明细一致（允许 10s 缓存差）。

### P4 界面（1.5–2 天）⏳

- 导航：一级「接入」（`/ui/access`），子页「日志」「接入点」；原 Hook 接入页迁入「接入点」；设置里不再放接入/存储页。
- 日志页：
  - 顶部右上角：只读状态 chips + "设置"跳转（单行）。
  - 中部：接入点卡片（kind 名称、请求数、命中率、P95、降级 Top、最近时间、小折线）；时间窗切换。
  - 底部：统一日志流（类型徽标/接入点/时间/入/出/状态/耗时/corr），搜索框，瀑布流加载，点开看详情。
- 设置页：「接入与日志」分组（查询日志保留天数 + 清空；插件运行日志档位/上限/保留 + 清空）。
- 验收：无写入控件出现在日志页；设置修改后日志页状态同步；深链 `settings#access-logs` 定位。

### P5 实时统计（0.5–1 天）⏳

- 明细只留 3 天（约 2–3 万行），`(caller_kind, ts)` 索引下 `GROUP BY` 毫秒级，加 10 秒内存缓存即可"实时"。
- 需要长周期趋势时加写时小时计数（`query_stats_hourly`，写 query_log 同事务 upsert），不跑批。

## 9 风险与回滚

| 风险 | 处置 |
| --- | --- |
| 两源分页重复/漏行 | 各自游标 + 合并后按 `(ts,id)` 稳定序；出现断档回退一页 |
| 清空日志误操作 | 二次确认 + audit + 仅设置页可触发 |
| 真实库迁移失败 | 迁移前整库备份；失败即停 daemon 还原 |
| 日志页性能 | 明细限 3 天 + 索引 + 10s 缓存；搜索先 LIKE，不引 FTS |
| Trace 体积 | 默认 off；summary 哈希化；轮转 + keep_days + max_bytes |
