## 阻塞问题（3 个）

### 问题 1：daemon 在 Windows 后台启动后立即退出 ⭐ 关键

**现象**：`node dist/app/main.js daemon` 启动后，日志打印 `daemon.start port=53000`，但几秒后进程消失，`netstat` 查不到端口。

**已尝试**：
- `await new Promise(() => {})` — 进程仍退出
- `setInterval(() => {}, 1 << 30)` — 未验证（用户中断前最后修改）
- PowerShell `Start-Process` — 同样退出

**思路**：
- Windows 后台运行 node 可能因 stdin/stdout 关闭而退出，尝试 `process.stdin.resume()`
- 或者不用后台 `&`，改用 `nohup` 或 Windows Service 方式
- 或者问题根本不在保活，而在 Fastify server 没有正确响应请求导致静默崩溃

### 问题 2：Fastify 与现有 `boot()` 架构的集成方式不确定

**当前做法**：`buildHttpApp()` 返回 `http.createServer(app)`，由 `boot()` 的 `listen()` 统一 `server.listen(port, host)`。

**风险**：Fastify 官方推荐 `app.listen()`，直接对 `server.listen()` 可能绕过 Fastify 内部初始化。

**思路**：
- 验证 `http.createServer(app)` 是否能正确处理 Fastify 路由
- 如果不能，需重构 `lifecycle.ts` 的 `BootOptions`，让 `handlerFactory` 返回 `{ listen(), close() }` 而不是 `http.Server`

### 问题 3：curl 走代理导致测试误导

**现象**：`curl http://127.0.0.1:53000/ui` 实际走了 `http_proxy=127.0.0.1:3008`（WorkBuddy 代理），返回 502，一度误以为是 daemon 崩溃。

**解决**：`curl --noproxy '*'` 可绕过。
