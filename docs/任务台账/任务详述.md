### Phase 0

#### P0-01 脚手架与依赖规则

- **目标**：pnpm workspace、TS strict、eslint、vitest、目录骨架、`dependency-cruiser` 五条 forbid 规则。
- **依据**：详设 §3.1 / §3.2。
- **产出**：`package.json`、`tsconfig.json`、`.dependency-cruiser.cjs`、空目录树。
- **验收**：`pnpm lint:deps` 通过；`pnpm test` 空跑通过；`pnpm build` 产出 `dist/`。
- **坑**：`noUncheckedIndexedAccess: true` 会让大量数组访问报错，早点开比晚点开省事。

#### P0-02 配置加载与校验

- **目标**：`config.toml` 全键解析 + zod 校验 + 默认值合并 + **未知键报错**。
- **依据**：详设 §3.6（全键表）。
- **产出**：`app/config.ts`、`config.example.toml`。
- **验收**：写一个拼错的键 → 启动失败且错误信息指出键名；删掉某键 → 用默认值。
- **坑**：`~` 展开要自己做（Node 不展开）；`archive_dir` 允许不存在（首次运行才创建）。

#### P0-03 日志与错误码

- **目标**：pino JSONL + `MoshiError` + code→HTTP/MCP 映射表。
- **依据**：详设 §1.5、§11.1。
- **产出**：`infra/log/logger.ts`、`domain/errors.ts`。
- **验收**：单测遍历每个 code，断言 `httpStatus` 与 `mcpCode` 符合详设表。
- **坑**：MCP 错误码只有少数几个合法值，不要自造；能降级的不要抛错。

#### P0-04 数据目录、单实例、端口

- **目标**：建 `~/.moshi/` 子目录、`daemon.lock`、固定端口 9836（2026-11-08 起，不再顺延）。
- **依据**：详设 §3.4 启动顺序；概设 §1.1 第 3 条、§1.4。
- **产出**：`app/lock.ts`、`app/lifecycle.ts`（部分）。
- **验收**：起两个实例，第二个打印"已在运行（pid/port）"并退出 0；杀掉第一个后能接管。
- **坑**：陈旧锁要能识别（pid 不存在 / 连不上）；Windows 上 `process.kill(pid, 0)` 行为不同。

#### P0-05 DB 打开、迁移、DDL v1

- **目标**：`openDb()` + PRAGMA + `migrations/001_init.sql`（详设 §2.2 全量）+ `user_version` + 迁移前备份。
- **依据**：详设 §2.2 / §2.7。
- **产出**：`infra/sqlite/db.ts`、`migrate.ts`、`migrations/001_init.sql`。
- **验收**：空目录 → 建库成功、`user_version=1`、表数正确；再跑一次幂等；把 `user_version` 改成 99 → 拒绝启动。
- **坑**：`fact_vec` 建表依赖 `sqlite-vec` 扩展，加载失败要**跳过而非失败**（详设 §2.2 末段）。

#### P0-06 触发器与视图

- **目标**：详设 §2.5 全部触发器 + `v_fact_degree` / `v_active_fact` / `v_orphan_ratio`。
- **依据**：详设 §2.5 / §2.6。
- **产出**：`migrations/001_init.sql` 的触发器段 + 5 条单测。
- **验收**：`UPDATE fact SET content=...` 抛 `E_IMMUTABLE`；改 `attrs.ext` 不抛；改 `attrs.frozen` 抛；插边后 `degree` +1，关边后 -1。
- **坑**：`json_extract` 对 `frozen` 的比较依赖**稳定序列化**，P0-08 的 `canonicalJson` 必须先做对。

#### P0-07 仓储层与生命周期字段专用方法

- **目标**：`factRepo` / `edgeRepo` / `entityRepo` / `auditRepo`；`strength` / `pool` / `access_count` 只经专用方法写。
- **依据**：详设 §3.2 第 3 条、§3.3。
- **产出**：`infra/sqlite/*Repo.ts`。
- **验收**：`grep -rn "UPDATE fact SET strength" src/core` 无结果；所有写路径都过 repo。
- **坑**：不要为了省事在 core 里写裸 SQL——这是 K2 正交化在代码层的唯一防线。

#### P0-08 domain 类型、不变量、哈希、时间

- **目标**：`types.ts` / `enums.ts` / `invariants.ts` / `hash.ts` / `time.ts`。
- **依据**：详设 §1.1–§1.4、§3.3。
- **产出**：五个文件 + 单测。
- **验收**：`assertFeatureSafe` 对 7 个生命周期字段全部抛错；`canonicalJson` 对键序/中文/浮点/不可序列化四类各一条断言。
- **坑**：`canonicalJson` 必须**抛错**而不是静默丢 `undefined`，否则两个不同对象哈希相同。

#### P0-09 五个规范化器

- **目标**：`normalizePort` / `Path` / `Pkg` / `Version` / `Process` + 别名表。
- **依据**：详设 §5.4。
- **产出**：`core/parse/normalizers.ts` + 30 条 fixture。
- **验收**：fixture 全过；`node`/`Node.js`/`nodejs` 归一为同一个 `pkg:node`。
- **坑**：路径规范化**不碰文件系统**（纯词法），否则未挂载的路径会失败。

#### P0-10 实体消解与身份键

- **目标**：三级消解（规则/向量/provisional）+ `canonical_key` / `value_hash`。
- **依据**：详设 §5.5 / §5.6 / §1.3；概设 §3.6.1 / §3.6.2。
- **产出**：`core/write/resolve.ts`、`identity.ts`。
- **验收**：同主体两次写入得到同一 `canonical_key`；规范化失败时建 `etype='unknown'` 的 provisional 实体且 key 非空。
- **坑**：**这是全系统最容易返工的地方**。先写 fixture 再写实现，不要反过来。

#### P0-11 幂等写入、冲突检测、审计

- **目标**：详设 §2.8 四种情形 + §5.7 冲突检测 + `audit` 写入。
- **依据**：详设 §2.8 / §5.7 / §5.8.3。
- **产出**：`core/write/conflict.ts`、`harvest.ts`（upsert 部分）。
- **验收**：四情形各一条单测；同一批 annotation 跑两次，`fact` 行数不变。
- **坑**：`INSERT ... ON CONFLICT DO UPDATE` 的 `changes()` 恒为 1，**不能用来区分插入与更新**，必须先 SELECT。

#### P0-12 置信先验、脱敏、隔离区

- **目标**：先验表 + 重复观测加成 + 8 条脱敏规则 + `quarantine`。
- **依据**：详设 §5.8 / §1.6 / §5.9。
- **产出**：`core/write/confidence.ts`、`redact.ts`、`quarantine.ts`。
- **验收**：8 条脱敏 fixture；先验表按"来源×类型"查表正确；`confidence<0.25` 进隔离区。
- **坑**：脱敏顺序（私钥块先于通用赋值），反了会漏。

#### P0-13 解析器框架 + 5 类 parser

- **目标**：`Parser` 接口 + 注册表 + 首批 12 条模式（详设 §5.3.1 的 #1–#17 里挑 P0 必需）。
- **依据**：详设 §5.3。
- **产出**：`core/parse/registry.ts`、`parsers/{pkg,git,proc,fs,build}.ts`、fixtures。
- **验收**：每个 parser ≥ 2 个 fixture（正常 + 空输出）；未识别工具只落 episode 不入图。
- **坑**：正则要锚定行首/行尾，否则会把日志里的无关行也匹配进来。

#### P0-14 会话适配器与游标

- **目标**：`SessionSource` 接口 + `ClaudeCodeAdapter` + `DshAdapter` + `GenericJsonlAdapter` + `cursors.json`。
- **依据**：详设 §5.2。
- **产出**：`core/adapters/*.ts`。
- **验收**：`moshi doctor --probe-source` 能 dump 前 3 行字段形状；文件截断/轮转/半行三种边界各一条测试。DSh 另验多帧 zstd 逐帧解压、游标停在完整帧后、半帧不消费。
- **坑**：**平台格式没有文档**，只能实测。适配器必须容忍未知字段与未知 type，否则升级即静默失效。DSh 的 `session.v*.jsonl.zstd` 是**追加写的多帧 zstd**，`node:zlib` 只解首帧，必须按 RFC 8878 扫帧边界。

#### Z-01C Hook 台账节点 + Magpie 适配器

- **目标**：自持一套钩子协议 `moshi-hook/1`，让任意 Agent 宿主用「投递信号」的方式把会话带进 moshi 台账：①用户消息前注入已有事实（可关）；②工具调用后投递写入信号（可关）；③回复生成前注入（Magpie 上不成立，如实标 `absent`）；④Stop/PreCompact/SessionEnd 入队并由后台无头进程抽取入库。Magpie 侧做真实实现（`packages/magpie-moshi`），Claude Code / DSH 只出设计。附带三开关图形界面（总开关 / 对话注入 / 注入已有事实 + 输出记忆）与「连接 Magpie」状态。
- **依据**：设计文档 `docs/设计-Hook台账节点与Magpie适配器.md`（§0–§15）；D-173（协议自持、budget、Magpie 2/7 时机）、D-174（`moshi_id`/`project_id` = sha256 前 32 hex，不加盐，不做设备/用户 ID）、D-175（项目三步识别与 `identity_source` 三档）；Magpie plugin-host `magpie.hooks` 只给 begin/onRequest 与 finish/onResponse，ctx 无 session/cwd/project，单钩子预算默认 1000ms。
- **产出**：`src/domain/identity.ts`（hash32 / `moshiId` / `projectId` / 项目三步识别）；`src/core/hook/{protocol,inject,render,state}.ts`；`src/app/http/routes/hook.ts`（`/api/hook/status|inject|record|flush|config|ping`）；`src/app/cli/commands/hook.ts`（`moshi hook trace|doctor`）；`src/ui` 的 `/hook/` 页；`packages/magpie-moshi`（零依赖 npm 包，`magpie.hooks` 入口，只用 fetch）；`docs/设计-Hook台账节点与Magpie适配器.md`。
- **验收**：AC-1 协议三态（`supported/absent/unknown`）在 status 里如实回报且 Magpie 的 `post_tool` 为 `absent` 并带原因；AC-2 `inject` 返回的 `additionalContext` 带 `§HOOK-MAIL` 段且不超过 cap，无证据时返回空且不占上下文；AC-3 同一轮重复投递 `record` 幂等（`raw_hash` 不变、episode 不增）；AC-4 身份：`.git` 仓库得 `identity_source=vcs`、自建标志得 `local`、无 cwd 得 `unknown` 并降级 `global`；AC-5 目录名就叫 `.moshi` 时不自建、不误认；AC-6 总开关关闭后所有端点回 `disabled` 且钩子零网络请求；AC-7 适配器在 daemon 不可达/超时时不改写 body、不抛错，`onResponse` 返回值被忽略；AC-8 `pnpm verify` + `pnpm build` 绿。
- **坑**：Magpie 改写后 `tools/tool_choice/function_call/functions/toolConfig/model/stream` 必须与原来**逐字节等值**（host 用 `JSON.stringify` 比对），所以胶水只能动 `messages`；`process.cwd()` 在 plugin-host 里是 Magpie 自己的目录，绝不能当工程目录用；钩子不能调模型（只投递信号），抽取在后台无头进程里做；`report()` 只能给固定枚举 + 字节数，禁止带查询/scope/凭据/召回内容；`.moshi/project.yaml` 一旦生成 `project_id` 永不改变（换 remote 也算同一工程需人工确认，见遗留 Z-01C-d）。
