00

读图约定：三眼看完这张图

这不是运行时拓扑。运行时只有 1 个 Node 进程（+ 0/1 个 Python 子进程），七层是代码里的依赖边界，靠目录结构与 lint 规则维持，不是七个服务。

竖着看：层级

宿主 → 接入 → 组装 → 领域 → 类型 → 适配 → 进程外。箭头一律指向被依赖方，越往下越纯：下层永远不认识上层。

横着看：边界

read 与 write 是两条正交支路，禁止互相 import；两者共享的东西只能下沉到 domain。app 是唯一能同时握住两支的地方。

顺着箭头看：流向

橙色是写入（对话 → 事实图），青色是读取（事实图 → 证据包 → 注入）。两条流在 SQLite 处交汇，但代码路径永不交叉。

宿主 接入 / 读取 组装 写入 治理 / 生命周期 类型 适配 / IO 实线 调用或依赖　虚线 可选 / 降级 / 禁止
三条不可越的线：① 依赖单向，`core` 不得 import `app/mcp/http`；② `domain` 不 import 任何 `infra`；③ 生命周期字段（strength / pool / access_count / archive_meta）一律不进 GAT 特征——白名单穷举，认识不到就抛错。

层代码位置职责硬边界
① 宿主进程外产生对话与工具输出；提供 session / cwdmoshi 不写它的提示词、不改内核、不接管工具循环
② 接入src/app/{hook,mcp,http} · packages/magpie-moshi把宿主协议翻译成 moshi-hook/1 或一次服务调用失败原样放行；单条 tool description ≤ 200 token
③ 组装src/app/{main,lifecycle,config,jobs,*Runner}读配置、抢锁、起服务、接调度、装配依赖唯一允许同时 import core/read 与 core/write
④ 领域src/core/{write,read,lifecycle,archive,collect,diag,ops}写入语义、召回算法、巩固与归档不 import app / mcp / http；read 与 write 不互引
⑤ 类型src/domain类型、枚举、不变量、作用域、身份哈希不 import 任何 infra / core / app；schema 变更只影响一处
⑥ 适配src/infra/{sqlite,vec,sidecar,fs,log,proc}唯一 IO 面：SQL、向量、子进程、文件、日志业务代码拿不到裸 SQL；生命周期字段读写只经专用方法
⑦ 进程外sidecar/ · ~/.moshi/ · 归档目录编码与打分、持久化、可分享资产可缺席：缺席即降级，不阻塞主链路
  • 进程只有两个

    daemon 与界面同进程同端口；sidecar 懒启动，5 分钟空闲卸权重、30 分钟退进程。冷启动不拉模型，<1s 到 /health 可用。

  • 单实例靠锁，不靠端口

    ~/.moshi/daemon.lock 写 pid/port；第二个实例探测到可连实例就直接退出 0。端口固定 9836，不顺延——MCP 地址已写进宿主配置。

  • UI 也由 daemon 托管

    同一 Fastify 实例挂 /ui、/api、/mcp、/hook，避免双端口、CORS 与跨进程状态同步。

  • 读写共享底座，不共享路径

    两支都落 infra/sqlite，但 core/read 与 core/write 之间没有一条 import——共享物全部下沉 domain。

  • 契约交点三处，代码交点三支

    契约：① annotation 行（collect 产出、write 消费）；② domain 的 Scope / Identity / Subgraph 类型；③ SQLite 连接由 app 注入——这三处不成 import 边。代码级另有单向引用：hook → read/write、lifecycle → read/write、collect → write。

  • lifecycle → read 是单向 import

    train-export 复用 read/subgraph 与 subgraph-payload。反方向不成立：read 过滤时读 strength、pool、epistemic_status，这些字段由 lifecycle 计算、read 只经 factRepo 取列值，不 import core/lifecycle。

  • archive 是纯下游

    它读图写 MD，从不反向修改事实。归档不是第二写层——L0 只有事实图一个写层。

  • collect 与 write 的契约是行，不是函数

    collect 只往 annotation 插行；write 只从 annotation 取行。两侧可独立重放。

  • 为什么单写者

    SQLite 虽支持并发读，但写事务串行更省心：避免"harvest 与 consolidate 同时改同一行"的锁竞争与语义竞态。读路径不受影响，WAL 下照常并发。

  • 错过触发点不补跑

    睡眠 / 关机后重启，只跑当前该跑的一轮。补跑会在启动瞬间叠加多轮 harvest，反而拖垮首查。

  • 链尾顺序不能颠倒

    事实 → 巩固 → schema → 社区。社区摘要依赖稳定的 ontology 与边集，提前跑只会产出过期摘要。

  • 投影可全量重建

    layout / summary / archive / degree 四类投影都能从事实图重建；/api/maintenance/rebuild 是逃生口，不靠备份。
