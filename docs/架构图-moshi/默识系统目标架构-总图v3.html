依赖只能向下 硬红线（禁止边） app 是唯一同时 import core/read 与 core/write 的地方；两者共享的东西只能下沉到 domain
  • read ↛ write：两条正交支路，禁止互相 import；运行时都碰同一个 SQLite，那是数据交汇，不是代码耦合。
  • core ↛ app / http：领域层不认识接入与组装，只接收已归一化的调用。
  • domain ↛ infra：类型层不碰 IO；业务代码拿不到裸 SQL，一律经 infra/sqlite 的专用方法。
  • Sidecar 可缺席：它是唯一允许「不在」的依赖——缺席即 no_sidecar，读取退化为纯符号，不阻塞主链路。

口径：目标形态；步骤编号（WR0–WR8 / RD1–RD9）沿用 v2，模块名与目录以代码为准。RD1（入口）与 RD2（分流）折叠在图 1 的「五面接入 · 装配」里，不在读链上重复画。
