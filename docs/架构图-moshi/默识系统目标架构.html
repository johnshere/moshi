00

读图约定：这是目标形态，不是现状快照

本页画的是主干收口之后应当长成的样子：一个能力只有一个函数，五个对接口只是壳。看的时候先认三件事：层是依赖边界，能力是可被调用的动作边界，主干是两端各一条数据通路。

竖着看：层

L5 边界域 → L4 接入层 → L3 装配层 → L2 能力层 → L1 机理层 → L0 不变量。箭头只指被依赖方；下层不认识上层。

横着看：接入面

hook / MCP / REST / CLI / UI 五件协议外套，各配一个装配层对接口；对接口只做校验、参数归一与渲染，再统一汇入服务装配，谁也不许直呼 L1 内部阶段。

顺着看：主干

出主干 = 一次召回（蓝），入主干 = 一次写入（琥珀）。两条主干在 SQLite 交汇，但代码路径永不交叉。

宿主 接入面 装配 / 能力 写入 读取 / 机理 治理 · 触发 · 红线 不变量 粗箭头 主干　实线 依赖
虚线 触发 / 只读 / 禁止
与 01A 的分工：01A 回答「现在有哪些模块、谁依赖谁」；本页回答「收口之后谁该在什么位置、谁只能做什么」。凡是两者不一致处，以本页为目标、以 01A 为现状。
01

六层总架构：主干纵穿，分支横挂

每一层只对下一层负责：边界域提供宿主与外部数据，接入层只做协议归一与渲染，装配层把入口接到对接口并注入 caller / scope / budget，能力层是唯一可被调用的动作，机理层给算法，不变量给编译期约束。两条主干（出=蓝、入=琥珀）从会话文件与宿主事件出发一路穿到 SQLite：L1 里各自展开成一条流水线（出链 7 段、入链 8 段）。能力节点第二行直接标了它落在哪一段，对接口第二行标了它能调哪些能力。

图 1 · 六层总架构与主干分层网格 · 静态 SVG · 可横向拖动 / 全屏看

图例：粗箭头 = 主干（出链蓝、入链琥珀）；细实线 = 依赖；虚线 = 触发、只读或可降级。横挂点只有四处：L5 宿主 → L4 接入面、L4 接入面 → L3 对接口、L3 对接口统一汇入服务装配、服务装配 → L2 能力、L2 能力 → L1 段落。会话文件是例外：它不经过接入层——scheduler 定时读它，collectRunner 扫出块，collect 落到 WR0；除此之外任何跨层直连都算越界。L1 两条主干由 core/{read,write,lifecycle,archive,collect,parse,hook,diag,ops} 承担，逐段细节见图 2 / 图 3。

层唯一的职责不许做的事
L5 宿主产生对话、发起请求；Magpie / Claude Code / DSH / CLI / 浏览器，外加宿主会话文件（CC/DSH 写，我们只读尾随）不直连 daemon 之外的任何东西
L4 接入层协议翻译、渲染、能力自报（caps）；hook 还要守 800ms 预算不组装参数、不查仓储、不写事实
L3 装配起进程、注入依赖、排调度、发权限；main 是唯一组合根不含业务判断，不写 SQL
L2 用例一个能力一个函数：参数、身份、预算、降级码、审计都在这里定不实现算法，不拼 SQL，不做渲染
L1 机理core：两条主干各一条流水线——出链（入口·预算→分流→三路召回→RRF+子图→模型→裁决+装箱→证据包）与入链（扫会话→脱敏→隔离→episode→解析→消解·幂等·冲突→事实图→投影）不读 config，不认 caller，不认识协议
L0 不变量类型、枚举、身份、scope、hash、纯函数不 import 任何 infra / core / app

存储（moshi.db / 归档 MD / 日志）与进程外 Python sidecar 都不是层：存储是用例与机理共同的落地端，只经仓储接口进入，interface 归 L0；sidecar 只是被 L1 调用的模型运行时（/encode · /score），可降级。宿主会话文件不是我们的存储，它作为外部输入挂在 L5。

脱敏先于落盘

W3 在 W5 之前，且必须作用在写库的同一份正文上；回填不算合规。

证据链 append-only

episode 只追加，靠 raw_hash + session 去重；永不 UPDATE、永不 DELETE。

harvest 唯一消费者

任何入口只入队；事实图的写只发生在 W7–W12，且只有队列里的 harvest 能到。

另外两条：幂等必须覆盖 A 全新 / B 完全重复（观测合并、不建新行）/ C 复活（撤销 valid_to 重新生效）/ D 不同取值（走冲突路径，按基数性收口或并存）四种情形（同一批重放不得产生第二份事实）；fact 表的写入者只有 W12，纠正走 correct 用例的同一套写路径，不许直调仓储 setter。

事实向量不在写事务里算：syncFactVectors（src/infra/vec/index.ts:123）由装配层在事务外补齐（src/app/main.ts 注入 sidecar 的 encode）；core/write 只保留 src/core/write/resolve.ts:49 的 vectorResolver 这个尚未注入的设计位（实体消解用），全仓 core/write 对 infra/sidecar 零 import。

05
