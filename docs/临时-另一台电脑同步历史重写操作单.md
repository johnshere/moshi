# 另一台电脑同步操作单

## 0 一句话

远端 `main` 的历史已在 2026-11-06 重写，旧提交 SHA 全部作废。本机**不要 `git pull`**，用 `git fetch` + `git reset --hard origin/main` 对齐。

## 1 背景：为什么不能 pull

- 2026-11-06 在办公室机器上用 `git filter-repo` 把 22 条误用了公司 Git 身份（公司姓名 / 公司邮箱）的提交，author / committer 统一改为 GitHub 个人身份（个人姓名 / 个人邮箱）。
- 只改身份字段：**文件内容（tree）、commit message、作者时间、提交时间、父子结构全部未变**（已对 135 条逐条校验，0 失败）。
- 代价：22 条本身 + 74 条后代，共 **75 条 SHA 变化**。所以本机旧 `main` 与远端新 `main` **分叉**，`pull` 会 merge 出重复提交和冲突。
- 旧历史完整备份在办公室机器：`E:\Workspace\.dsh\temp\moshi-a2-20261106\moshi-backup.bundle`（不在本机，需要回滚再找办公室机器）。
- 如果本机 `main` 还是 `a15a442…`，说明尚未同步；远端新 HEAD 以 `git ls-remote origin main` 为准。

## 2 前置检查（全部通过再往下）

在本机仓库根目录执行：

```powershell
git status -sb
git fetch --prune origin
git log --oneline origin/main..main
git config --global user.email
```

判定：

- `git status -sb` 必须干净（没有已修改/已暂存的文件）；有改动先 commit 或 stash。
- `git log --oneline origin/main..main` **必须为空**。有输出 = 本机有未推送提交，**停下，别 reset**，把输出发给办公室机器处理。
- `git config --global user.email` 记下结果，见 §4。

## 3 对齐（唯一正确操作）

```powershell
git reset --hard origin/main
git log -1 --oneline
git status -sb
git rev-list --count main
```

预期：

- `git log -1 --oneline` 显示最新提交（本文件引入的那条 `docs: 临时操作单……`）；
- `git status -sb` 显示 `## main...origin/main`，无 `ahead` / `behind`；
- 提交数 = **136**（重写后的 135 条 + 本操作单 1 条）；
- 工作区文件内容与 reset 前**完全一致**（本次重写没改任何文件内容，只改了提交身份和 SHA）。

**不要做**：`git pull`、`git pull --rebase`、`git merge origin/main`、`git rebase`——任何一个都会把旧历史带回来或造出重复提交。

## 4 提交身份检查（防止以后再产出公司身份）

```powershell
git config --global user.name
git config --global user.email
```

- 若显示个人身份（姓名 / 邮箱都与 GitHub 账号一致，不是公司域名）：通过。
- 若显示公司身份（公司姓名 / 公司邮箱）：本机全局配置需要加与办公室机器一致的 `includeIf`（只按 remote 切换，不影响公司 GitLab 仓库）：

`~/.gitconfig` 末尾追加：

```ini
[includeIf "hasconfig:remote.*.url:https://github.com/**"]
    path = ~/.gitconfig-github
[includeIf "hasconfig:remote.*.url:git@github.com:*/**"]
    path = ~/.gitconfig-github
```

新建 `~/.gitconfig-github`：

```ini
[user]
    name = <GitHub 用户名>
    email = <GitHub 账号邮箱>
```

上面两个值填成与办公室机器 `~/.gitconfig-github` 相同的个人身份；不要填公司姓名 / 公司邮箱。

注意事项：

- SSH 那行必须写 `git@github.com:*/**`；写成 `git@github.com:**` 不生效（`:` 后的 `**` 不跨 `/`）。
- 在 moshi 仓库里执行 `git config user.name`，应显示个人身份；在任意公司 GitLab 仓库里应仍是公司身份。
- 改完配置属于环境变动，按规矩先暂停观察，确认本仓库与公司仓库各取各的身份后再继续提交。

## 5 常见问题

- **reset 后 reflog 里还有旧历史**：正常。别从旧提交开分支再推；reflog 过阵子自动过期。
- **工作区有未跟踪文件**：`reset --hard` 不动未跟踪文件，保留即可，不要为了"对齐"去删。
- **§2 发现本机有未推送提交**：停。把 `git log --oneline origin/main..main` 的输出发给办公室机器，由那边 rebase / cherry-pick 到新历史后再同步；不要自行 merge。
- **reset 后觉得文件不对**：先 `git status`，再核对 `git rev-parse HEAD` 与 `git rev-parse origin/main` 是否相等；内容层面的兜底是 `git rev-parse HEAD^{tree}` 应为 `a93bbbb7f0f93717a3260276594ba1c750f4331e`。
- **旧 commit 链接打不开**：预期行为。旧 SHA 已不在任何分支上（GitHub 后台 GC 前直链可能还能访问，但不参与贡献图）。
