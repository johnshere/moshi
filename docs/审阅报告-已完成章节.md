## 一、主干问题（3 个，按严重度排序）

### 1. 真实库与当前代码严重脱节：迁移卡在 v2，落后 3 个版本

| 项 | 内容 |
| --- | --- |
| **现象** | 真实库 `user_version = 2`，代码 `TARGET_VERSION = 5`（`src/infra/sqlite/migrate.ts:18`） |
| **证据** | 真实库实测 `user_version: 2`；003_protocol（`annotation.origin`）、004_edges（`edge.provenance`）、005_direct_write（`fact.origin/session_id/turn/batch_id`）从未在真实库执行过 |
| **影响** | P2-20~23 的全部功能在真实库**无 schema 支撑**：采集协议 origin 列缺失、边抽取 provenance 列缺失、直写闸门 batch_id 缺失。一旦真实库跑 P2-22/23 代码会直接失败或静默无效果 |
| **根因** | P1-25（002 迁移）之后，真实库 daemon 再未以当前代码启动过；所有 P2 开发/验收都在 `.dsh/temp/*` 的 seed 库上进行（新建库直接建到 v5，掩盖了真实库落后） |
| **方案** | 启动一次真实库 daemon（或直接跑迁移）即自动补到 v5；注意先确认真实 config 端口不与验收 daemon（53000/pid 10772）冲突，迁移会自动执行 |
