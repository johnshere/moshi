## 5. 已知问题（本次实测发现）

1. **`MOSHI_HOME` 不生效**：daemon 照旧读 `~/.moshi/config.toml`。要隔离测试必须换 `storage.data_dir` 或临时改配置。测试时我直接在 `~/.moshi/moshi.db` 里写入了 3 条测试事实与 1 条 episode（`fact_hook_live_1..3`、`ep_01m70n2pwp1j94kjgm7v940br2`），并给 `~/.moshi/config.toml` 追加了 `[hook] capture_reply=false / enabled=true`（这是开关接口自身的正常写盘结果，不是手工改的）。
2. **`insertFact` 工厂不同步 FTS**：走工厂直接插的 fact 搜不到，必须再 `syncMissingFts(db)`——工程既有约定（`tests/unit/search.test.ts:11` 注释说明过），联调时踩了一次。
3. **注入身份里的 `moshi_id` 恒为 null**：插件目前只传 `session.id`，服务端 `sessionMoshiId` 的输入尚未从宿主补齐（`identity.ts` 已实现，接线放在 Z-01C-a）。
4. **召回缺 `degraded=["no_sidecar"]`**：daemon 的 `buildHttpApp` 没有注入 `encode/score`，钩子走的是 BM25+PPR 通道；融合结果仍正确，但语义通道这一档没带上，界面上看到的是"少了半条腿"。接线放在 Z-01C-b。
5. **`hook status` 的空 `remote` 占位**（§3.4 坑 2）。

## 6. 没有验证到的（如实记录）

- **真实 Magpie plugin-host 往返**：没有往 `C:\Users\john\.cache\magpie\plugin-host\` 里装包。原因：那是本机**正在使用**的 Magpie 实例（pid 3696），装一个会改用户全局配置的中间件插件属于状态变更，需要用户点头。本次验证到的是"插件导出契约 + 真实 daemon HTTP 往返"，中间那一跳（Magpie 用 `magpie.hooks` 载入并把它接进 1000ms 预算）**未实测**。
- **真实上游模型请求**：没有让 Magpie 转发一次真实对话，所以"注入块在真实 session 里是否被模型正确理解"未验证。
- **召回质量**：只验证了"有证据就能注、没证据就不注"，没有做相关性评估（那属于 eval 体系的活）。
- **Claude Code / DSH 入口**：按设计只做了文档，未实现、未测试。
