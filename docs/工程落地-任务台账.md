# 默识工程落地任务台账

> **这份文档是给执行者（Agent 或人）读和写的。**
> 代码怎么写看 `详设`；为什么这么做看 `概设` / `综述`。这里只回答三件事：**现在做到哪了、下一步做什么、怎么算做完了。**

---

## 0 使用协议（每次开工必读）

### 0.1 三份文档的分工

| 文档 | 回答 | 什么时候看 |
| --- | --- | --- |
| `综述-默识记忆系统.md` | 该不该做、有没有证据 | **几乎不看**。只在质疑某个方向时查 |
| `工程概设-默识记忆系统.md` | 做成什么样、为什么这么定 | 需要判断"这个设计能不能改"时看对应章节 |
| `详设-默识记忆系统.md` | 具体怎么写：字段、算法、接口、参数 | **每次写代码前看对应小节** |
| **本文** | 现在做到哪、下一步做什么 | **每次开工第一件事** |

**规则：本文不复制详设的内容。** 任务详情只给"做什么 + 看哪一节 + 怎么验收"。想改实现细节，去改详设；本文只记进度。

### 0.2 状态机

```
TODO ──开始──> WIP ──验收通过──> DONE
                 │
                 ├──卡住──> BLOCKED ──问题解决──> WIP
                 └──不再需要──> DROPPED（必须在 §5 写原因）
```

| 状态 | 含义 | 允许的下一步 |
| --- | --- | --- |
| `TODO` | 未开始 | 依赖满足后可开工 |
| `WIP` | 正在做，**同一时间只允许一个** | 完成或阻塞 |
| `BLOCKED` | 缺信息/缺决策/外部故障 | 等 §5 的问题有结论 |
| `DONE` | 验收命令跑过、输出记在 §6 | 不可再改，除非 §5 有决策记录 |
| `DROPPED` | 主动放弃 | 必须在 §5 写明原因与替代方案 |

### 0.3 一次工作循环（严格按此顺序）

```
1. 读 §1 进度快照（30 秒）
2. 读 §6 最后 5 条日志（知道上次做到哪、有没有半成品）
3. 若 §1 有 WIP → 接着做那个；否则按 §3 顺序取第一个"依赖全 DONE 的 TODO"
4. 读该任务的 §4 详情 + 它引用的详设小节
5. 跑一次该任务的验收命令，确认当前真实状态（不要相信台账，相信代码）
6. 改状态为 WIP，在 §1 记开始时间
7. 写代码
8. 跑验收命令，把关键输出抄进 §6 日志
9. 改状态为 DONE，更新 §1 快照
```

**第 5 步不能省。** 台账可能滞后于代码（上一次会话可能改完代码没来得及改台账）。**代码是事实，台账是记录**——两者冲突时以代码为准，并立即修正台账。

### 0.4 上下文恢复协议（压缩/新会话后）

新会话开始时，你可能什么都不记得。按这个顺序恢复，**不要试图读全部文档**：

```
① 本文 §1（进度快照）                    → 30 秒，知道全局位置
② 本文 §6 最后 5 条日志                  → 1 分钟，知道最近发生了什么
③ 本文 §3 表格中状态为 WIP/BLOCKED 的行  → 30 秒
④ 对应任务的 §4 详情                     → 2 分钟
⑤ `git status` + `git log --oneline -5`  → 确认代码真实状态
⑥ 跑该任务的验收命令                     → 确认是否其实已经做完
```

**⑤⑥ 是关键**：上一次会话可能在"代码写完但没标 DONE"的状态结束。不验证就重做，会浪费一整轮。

### 0.5 完成定义（DoD）

一个任务只有同时满足以下五条，才能标 `DONE`：

1. **代码已落盘**，`pnpm build` 通过；
2. **验收命令跑过**，关键输出已抄进 §6（不是"应该能过"，是"跑过并且过了"）；
3. **该模块的关键分支有单测**（详设 §12.1 列了必测项）；
4. **新增代码里没有未记录的 `TODO` / `FIXME`**（有就记进 §5）；
5. **三处已更新**：§1 快照、§3 状态、§6 日志。

缺任何一条都不算 DONE。**宁可标 WIP，不要虚标 DONE**——虚标会让后续任务建立在不存在的地基上，返工成本是十倍。

### 0.6 遇到不确定时怎么办

| 情况 | 做法 |
| --- | --- |
| 详设写清楚了 | 照做 |
| 详设没写，但概设有原则 | 按原则选一个最简单的实现，**记进 §5 决策记录**，继续 |
| 详设和概设冲突 | **以概设为准**，改详设，记 §5 |
| 两者都没写 | 选最保守的方案（不做额外功能、不猜业务规则），记 §5，继续 |
| 需要外部信息（平台格式、库 API） | 先用 `--probe` 类命令实测，把实测结果记进 §5，再实现 |
| 真的做不下去 | 标 `BLOCKED`，§5 写清"试过什么、卡在哪、需要谁决定"，**然后去做下一个任务**——不要停在原地 |

**最重要的一条：不要为了"等一个答案"而停工。** 80 个任务里绝大多数互不阻塞，卡住一个就换一个。

### 0.7 禁止事项

| 禁止 | 原因 |
| --- | --- |
| 改概设的方向性决策 | 那是月级文档，改了会与综述脱节。有异议写 §5 |
| 跳过验收命令标 DONE | 见 §0.5 |
| 一次改多个任务状态 | 状态机失效后无法判断真实进度 |
| 删除 §6 的历史日志 | 它是唯一的执行轨迹，只能追加 |
| 在任务里"顺手"加功能 | 范围蔓延是长周期任务失败的第一原因。想到的加进 §5 的"想法池" |
| 用 `rm` 清理 `~/.moshi` | 那是用户数据。测试用临时目录 |

### 0.8 日志格式（§6 追加用）

每条日志一行，格式固定，便于 grep：

```
YYYY-MM-DD HH:mm | <任务ID> | <状态变化> | <一句话结果> | <验收命令输出摘要>
```

例：

```
2026-11-02 14:32 | P0-05 | DONE | DDL 建成，user_version=1 | migrate ok, 14 tables, 0.8s
2026-11-02 16:10 | P0-06 | BLOCKED | 触发器 json_extract 比较在 SQLite 3.40 上行为不同 | need version pin
```

## 4 任务详述

> 每项只写五件事：**做什么、看哪节、产出什么、怎么验收、坑在哪**。
> 实现细节一律不在这里重复——去详设对应小节。

### Phase 0

#### P0-01 脚手架与依赖规则

- **目标**：pnpm workspace、TS strict、eslint、vitest、目录骨架、`dependency-cruiser` 五条 forbid 规则。
- **依据**：详设 §3.1 / §3.2。
- **产出**：`package.json`、`tsconfig.json`、`.dependency-cruiser.cjs`、空目录树。
- **验收**：`pnpm lint:deps` 通过；`pnpm test` 空跑通过；`pnpm build` 产出 `dist/`。
- **坑**：`noUncheckedIndexedAccess: true` 会让大量数组访问报错，早点开比晚点开省事。

#### P0-02 配置加载与校验

- **目标**：`config.toml` 全键解析 + zod 校验 + 默认值合并 + **未知键报错**。
- **依据**：详设 §3.6（全键表）。
- **产出**：`app/config.ts`、`config.example.toml`。
- **验收**：写一个拼错的键 → 启动失败且错误信息指出键名；删掉某键 → 用默认值。
- **坑**：`~` 展开要自己做（Node 不展开）；`archive_dir` 允许不存在（首次运行才创建）。

#### P0-03 日志与错误码

- **目标**：pino JSONL + `MoshiError` + code→HTTP/MCP 映射表。
- **依据**：详设 §1.5、§11.1。
- **产出**：`infra/log/logger.ts`、`domain/errors.ts`。
- **验收**：单测遍历每个 code，断言 `httpStatus` 与 `mcpCode` 符合详设表。
- **坑**：MCP 错误码只有少数几个合法值，不要自造；能降级的不要抛错。

#### P0-04 数据目录、单实例、端口

- **目标**：建 `~/.moshi/` 子目录、`daemon.lock`、53000–53020 端口探测。
- **依据**：详设 §3.4 启动顺序；概设 §1.1 第 3 条、§1.4。
- **产出**：`app/lock.ts`、`app/lifecycle.ts`（部分）。
- **验收**：起两个实例，第二个打印"已在运行（pid/port）"并退出 0；杀掉第一个后能接管。
- **坑**：陈旧锁要能识别（pid 不存在 / 连不上）；Windows 上 `process.kill(pid, 0)` 行为不同。

#### P0-05 DB 打开、迁移、DDL v1

- **目标**：`openDb()` + PRAGMA + `migrations/001_init.sql`（详设 §2.2 全量）+ `user_version` + 迁移前备份。
- **依据**：详设 §2.2 / §2.7。
- **产出**：`infra/sqlite/db.ts`、`migrate.ts`、`migrations/001_init.sql`。
